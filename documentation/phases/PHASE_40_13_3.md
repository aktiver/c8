# Phase 40.13.3 — Bounded parallel SPARQL conformance foundation

Phase 40.13.3 is the first implementation increment after the Phase 40.13 production engineering plan. It advances the SPARQL correctness workstream without claiming that the database is complete or production-qualified.

## Delivered

- The pinned W3C manifest runner now inventories every locked test deterministically, executes independent cases through a bounded multicore pool, detects cgroup CPU quotas/cpusets, reserves coordinator capacity, and forces each child process to one native BLAS/OpenMP/Rayon lane.
- Every case has an isolated working directory, a wall-clock timeout, bounded captured output, deterministic report ordering and an atomically published JSON report.
- Manifest actions and results must resolve to regular, non-symlink files inside the pinned suite root.
- The Rust case driver now performs official `TestTrigEval` dataset comparison after base-IRI-aware parsing and blank-node canonicalization. This makes all 143 TriG evaluation cases executable in addition to syntax tests.
- A schema-validated SPARQL 1.1 functional matrix separates parser, scalar reference, distributed and online status. Its claim remains `inventory`; partial and missing behavior stays visible.
- The Phase 39.2 gate builds the Rust case driver once, then reuses the binary across the bounded worker pool instead of invoking Cargo for every test.

## Autoscaling and HPC boundary

This phase improves node-local conformance throughput and resource discipline. It consumes the existing Phase 40.13.2 Kubernetes workload autoscaling contract, including the `ngkg_admission_pending` external metric, but it does not claim a live multinode Kubernetes qualification. Production HPA/KEDA behavior still requires a real metrics adapter, cluster load tests and failure injection.

## Explicitly incomplete

- The locked suite contains protocol, service-description and entailment-regime cases that are outside the current case driver; these remain reported as unsupported rather than silently skipped. Entailment cases do not run under simple RDF semantics and accidentally count as passes.
- Passing the scalar W3C query cases does not establish distributed or online equivalence. Failures are backlog inputs, not waivers.
- Exact HermiT reasoning is not yet wired into every online query path.
- Ontology alignment remains absent and out of scope.

## Next implementation increment

Use the Phase 40.13.3 W3C failure report to close parser/reference defects by feature family. In parallel with that correctness convergence, implement distributed algebra parity in this order: active dataset and graph semantics, joins/OPTIONAL/MINUS/UNION, grouping/aggregates/modifiers, property-path frontier execution, then allowlisted bounded `SERVICE`. Every distributed operator must compare its multiset or graph result with the scalar reference implementation before the online route is enabled.
