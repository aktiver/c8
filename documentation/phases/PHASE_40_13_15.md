# Phase 40.13.15 — atomic publication and query activation

The cloud-source pipeline remains invisible until one activation worker verifies the exact semantic compilation, authorization/OWL qualification, and offline reasoning roots plus all partition artifacts. The resulting activation manifest binds every semantic identity and is immutable.

PostgreSQL inserts the activation and certified snapshot in one transaction. Publication uses a parent-snapshot compare-and-swap and retires the old snapshot inside that transaction; online replicas resolve only the catalog's active `PUBLISHED` row. Failed verification, a missing partition, checksum mismatch, inconsistent ontology, stale parent, or interrupted worker cannot expose partial content.

Expensive stages use stable logical partitions and Kubernetes Indexed Jobs. Kueue caps active work while pending pods drive node autoscaling; all worker concurrency and scratch use is bounded. Publication stays single-writer because it is a correctness barrier, not a throughput kernel.

The scalar compatibility image is limited to 64 GiB. Phase 40.13.16 must activate larger snapshots directly from partition-native semantic artifacts and distribute the complete SPARQL algebra. Payload hydration is unavailable for the cloud activation until a real locator and payload layout is certified.

Only authorized asserted `https://c8-next-generation.io/*/*/semkg` graphs enter OWL assembly. This phase contains no ontology alignment or raw-data mapping.
