# Phase 40.13.13 — Deterministic OWL 2 DL Snapshot Qualification

Phase 40.13.13 consumes the inactive semantic-compilation root from Phase 40.13.12. It selects
only explicitly authorized `https://c8-next-generation.io/<scope>/<subdomain>/semkg` graphs,
resolves checksum-pinned imports, constructs a synthetic snapshot ontology, and requires pinned
HermiT 1.4.5.519 to prove the combined ontology is in OWL 2 DL and logically consistent.

This is ontology assembly, not ontology alignment. Inputs are already-authored RDF/OWL axioms;
the system does not infer schemas from raw data, match concepts, rewrite source models, or create
alignment graphs. Closure and provenance graphs are never eligible asserted inputs.

## Distributed execution

1. `cloud-ontology-project` is an Indexed Job with one completion per stable semantic partition.
   Each pod verifies the semantic root, authorization request, partition manifest, and `facts.nq`,
   then emits sorted N-Triples runs for authorized asserted graphs only.
2. `cloud-ontology-assemble` starts after every projection index completes. It verifies exact
   partition coverage, merges each graph into one ontology document, validates one ontology header
   per document, resolves every `owl:imports` edge through ontology/version aliases, and rejects
   every unpinned import.
3. `cloud-ontology-qualify` materializes the exact assembled document set and datatype policy,
   runs the checksum-pinned OWLAPI/HermiT adapter with a bounded heap and timeout, then verifies
   the signature, profile, consistency, report, and all cross-artifact hashes before emitting an
   inactive qualification root.

Projection pods use the Kueue `reasoning` flavor and a topology-independent logical partition
layout. Pending Indexed Jobs can drive Kubernetes Cluster Autoscaler scale-up. Parallelism changes
only scheduling; the projection completion hash, document set, aggregate input hash, authorized
graph hash, datatype-policy hash, and synthetic ontology hash must remain identical.

Global OWL 2 DL profile and consistency are not decomposed into per-partition guesses. HermiT
receives the complete local import closure in one memory-heavy reasoning pod because arbitrary
OWL 2 DL consistency is global. The production values reserve a 96-GiB heap inside a 128-GiB pod,
leaving capacity for OWLAPI, native memory, Rust, file buffers, and the operating system.

## Fail-closed and publication boundary

- Missing projection indexes, mismatched checksums, duplicate ontology aliases, unresolved imports,
  unsupported datatypes, OWL 2 DL profile violations, inconsistency, timeout, OOM, or a failed
  reasoner process produce no successful qualification root.
- The root binds tenant, dataset, operation, snapshot, semantic root, authorized graph set,
  authorization policy, datatype policy, ontology document set, synthetic ontology identity,
  HermiT version, profile evidence, and consistency evidence.
- `publicationState` remains `inactive`. Phase 40.13.15 owns atomic query activation; Phase
  40.13.14 must first build and HermiT-verify distributed finite closure and semantic indexes.
