# Phase 40.13.22 — Standards and differential qualification

Phase 40.13.22 turns standards claims into content-bound, machine-verifiable evidence. It covers the applicable RDF 1.1 TriG syntax/evaluation suites, SPARQL 1.1 syntax and every query form, result formats, protocol dataset parameters and negotiation, service description, secured federation, OWL 2 Direct-Semantics, and product failure cases. The W3C RDF test repository remains pinned to commit `8af71fed933539d09d5f4658fb1ea7ba4c8e30b9`; Apache Jena is pinned to 6.2.0 and HermiT to 1.4.5.519.

Every concrete case receives a stable ID, a SHA-256 over its canonical descriptor and referenced-input digests, an independent oracle, an expected terminal outcome, and a topology-independent partition. Independent cases run concurrently within a cgroup-aware process pool and across Kubernetes Indexed Job completions. Nested native and JVM lane counts are constrained to prevent oversubscription. Kueue can admit the job onto the existing autoscaled `sparql-query-processing` pool on RKE/RKE2, EKS, AKS, or GKE; scaling changes elapsed time, not assignments or evidence.

The driver protocol is deliberately small. NGKG and its W3C, Jena, or HermiT authority must each emit one complete terminal observation. Successful cases compare canonical semantic-result SHA-256 values. Negative cases compare stable error classes and forbid partial output. SELECT comparison retains duplicates, treats order as significant only when required, and compares RDF terms rather than display strings. RDF graph and TriG comparisons require blank-node-independent canonicalization. Serialization bytes alone are never treated as graph equivalence.

Each worker atomically writes one partition report only after every assigned case completes. The final merger requires exactly one report for every dense partition, exact plan identity, unique workers, exact case assignment, no duplicate delivery, all declared standards families, and all three authority classes. Any timeout, oversized output, missing or extra field, unsupported case, missing partition, result mismatch, failure-class mismatch, or partial answer prevents certificate creation. A valid certificate has `mismatchCount: 0`, `missingCaseCount: 0`, and `complete: true` by construction.

The included static/executable test uses synthetic independent drivers to exercise successful SPARQL, HermiT-routed OWL, negative-case, multi-partition, and merge-barrier behavior. Existing recorded W3C evidence from earlier phases remains inherited, but it is not relabeled as Phase 40.13.22 production evidence. Release qualification still requires fetching the exact pinned W3C commit, building the pinned Jena/HermiT adapters, expanding every applicable test to an individual case, running the distributed job against release images, and retaining the signed report set and zero-mismatch certificate.

This phase adds no ontology alignment, schema matching, or raw-data mapping. Phase 40.13.23 is next: reproducible performance and capacity qualification against Apache Jena on representative enterprise datasets.
