# Phase 36 — Executable compliance baseline

## Objective

Phase 36 converts the Phase 35 certified-query implementation into a fail-closed compliance baseline whose semantic claims are bound to executable evidence. It does not enable a SPARQL 1.1, union-default, OWL Direct, or OWL 2 DL public claim.

## Implemented

- The Rust workspace includes the dedicated `ngkg-dataset` semantic contract crate.
- Fresh local query results are canonicalized and compared with the versioned offline RDF-term multiset certificate before a successful result is returned.
- Query-cache keys bind tenant, snapshot, manifest, serving root, exact query hash, authorized graph-set hash, active-dataset hash, dataset-selection source, and hydration mode.
- API and online-serving bearer-token files are checksum-bound and reject unknown scopes. `sources:write` and `queries:execute` are explicit scopes; query identities require graph authorization labels.
- The HermiT adapter and Rust reasoner client use report format version 2. The combined ontology is checked with OWLAPI `OWL2DLProfile`, imports are resolved from checksum-bound local documents, and HermiT consistency is mandatory.
- The control API accepts bounded, streaming UTF-8 `application/trig` uploads. Request bytes are hashed while streaming to local scratch, syntax is validated with the RDF parser, IRI-named NGKG subdomain graphs are required, blank-node graph names are rejected, and immutable source plus metadata objects are checksum-verified in the artifact store.
- Control-plane and online OpenAPI contracts are synchronized with the runtime models.
- `scripts/ci_release.sh` requires Cargo, Maven, Helm, kubectl, `Cargo.lock`, Rust format/lint/tests, Maven verification, Helm validation, Kubernetes server-side dry-run, and RKE2 preflight.
- The control API has a real `autoscaling/v2` HPA. Its CPU and memory targets remain at or below 80 percent, while each pod has bounded source-upload lanes, memory, CPU, and ephemeral storage.
- The official W3C `w3c/rdf-tests` source is immutable-dependency locked at commit `8af71fed933539d09d5f4658fb1ea7ba4c8e30b9`. `scripts/fetch_w3c_conformance.py` fetches that exact Git object under a cache lock and rejects origin drift, commit drift, dirty worktrees, missing manifests, symlinks, or empty manifests.

## HPC and enterprise behavior

Large TriG requests are not accumulated in RAM. They are streamed to bounded scratch storage, hashed incrementally, parsed from file, and then transferred to immutable object storage using the artifact store's single-put or multipart path. Per-pod upload concurrency is intentionally bounded; Kubernetes adds API replicas under load rather than allowing one process to oversubscribe memory or local storage.

The existing query plane retains bounded Tokio thread pools, Arrow IPC exchange, checksum-verified NVMe spools, Grace hash joins, Parquet hydration, bounded caches, and admission control. Kubernetes horizontal scaling is a separate layer from intra-pod parallelism.

## Acceptance criteria

Phase 36 is qualified only when all of the following execute successfully on the candidate commit:

- `cargo fmt --all --check`.
- locked workspace Clippy with warnings denied.
- locked Rust tests for every workspace target and feature.
- Maven `verify` for the version-locked HermiT adapter.
- strict JSON/YAML/OpenAPI structural validation.
- Helm lint/render for approved platform and workload values.
- Kubernetes server-side dry-run.
- RKE2 preflight with the required metrics and cluster-autoscaler dependencies.
- Fetch/verify the immutable W3C RDF 1.1 TriG and SPARQL 1.1 query/result/protocol/service-description/entailment manifests from the locked suite snapshot.
- A checked-in `Cargo.lock` generated by Cargo for the pinned workspace.

## Current boundary

The code in this cumulative tree contains the Phase 36 implementation work, but this environment does not contain Cargo, Maven, Helm, or kubectl. Therefore the phase remains an implementation candidate and the public standards feature gates remain disabled. No missing build or deployment gate is treated as a pass.
