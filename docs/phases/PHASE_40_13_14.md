# Phase 40.13.14 — Distributed Offline Reasoning

Phase 40.13.14 physically compiles the checksum-bound finite named consequences emitted by the exact HermiT 1.4.5.519 snapshot qualification. It does not invent a distributed OWL rule subset, treat an incomplete rule closure as complete, align ontologies, map raw data, or publish a snapshot.

## Semantic boundary

- Input authority is only the authorized, pinned-import, OWL 2 DL-qualified Phase 40.13.13 root and its exact `finite-closure.nt` hash.
- HermiT has already applied OWL 2 Direct Semantics, including property-chain, equality, datatype, and cardinality effects observable in the finite named consequence set.
- The materialization certificate covers only the finite named consequences HermiT emitted. All uncovered or unknown queries continue to exact online HermiT.
- Support IDs bind exact consequence bytes to the qualification root and stable partition. They are answer-support identities, not fabricated minimal proof DAGs.

## Distributed execution

1. `cloud-offline-plan` validates the exact root/closure and produces bounded external-sort runs assigned by stable content hash.
2. `cloud-offline-partition` is an Indexed Kubernetes Job. Each completion merges one logical partition and emits closure N-Quads, Parquet, class/property extents, hierarchy extents, equality membership, and proof-support rows.
3. `cloud-offline-finalize` verifies every remote artifact and completion, constructs equality components with bounded external merge, and writes one inactive completeness root.

The default layout has 4,096 logical partitions and at most 256 concurrently active one-CPU reducer pods. Kueue admits reasoning work against its ResourceFlavor; pending Indexed Job pods let the Kubernetes node autoscaler add reasoning nodes. Retries, rescheduling, and cluster size never affect logical partition identity or output bytes.

## Fail-closed behavior

No root is created when the qualification identity, HermiT version, finite closure checksum/count, plan, run, partition, artifact, or completion barrier differs. This phase deliberately leaves `publicationState=inactive`; Phase 40.13.15 must separately certify and atomically publish it.
