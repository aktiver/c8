# Phase 40.13.10 — named datasets and existing-cloud TriG acquisition

Phase 40.13.10 adds a human-facing dataset identity and a read-only existing-cloud source
acquisition lane. Dataset names are tenant-scoped generic slugs. `supply_chain`,
`clinical_nutrition`, `oncology`, and `loyalty_graph` are examples only; a name has no
schema, ontology, mapping, or alignment meaning. The catalog creates the opaque dataset UUID and
stable entity-identity namespace and returns them as machine metadata.

The public control-plane flow begins with:

```http
POST /v1/datasets
Content-Type: application/json

{"name":"oncology","policyVersion":"owl-direct-v1"}
```

An existing bucket import is then accepted through the readable name:

```http
POST /v1/datasets/oncology/imports
Idempotency-Key: 01J-EXAMPLE-IMMUTABLE-REQUEST
Content-Type: application/json

{
  "provider": "aws-s3",
  "bucket": "existing-rdf-production",
  "accountName": null,
  "prefix": "published/",
  "objectKeys": [],
  "includePatterns": ["**/*.trig"],
  "excludeSegments": ["alignment", "closure", "provenance"],
  "identityRef": "ngkg-oncology-source-reader",
  "versionPolicy": "require-immutable-checksum",
  "parentSnapshotId": null,
  "publicationPolicy": "manual-after-certification",
  "resourceProfile": "distributed-hpc-v1",
  "maxSourceBytes": 549755813888,
  "maxSourceObjects": 100000,
  "logicalPartitions": 256
}
```

The request contains no cloud secret. `identityRef` names an existing Kubernetes ServiceAccount
whose AWS/Azure/GCP workload identity has read-only access to the existing bucket. The operator
creates an immutable `NgkgSourceImport`, a read-only static CSI volume/PVC, a resource-name-scoped
worker RoleBinding, and a Kueue-managed Job on the `source-ingestion` node pool. AWS Mountpoint,
Azure Blob CSI, or GCS FUSE must already be installed and qualified by the cluster operator.

The loader rejects symlinks and path escapes, selects only `.trig` paths, and rejects paths whose
segments are `alignment`, `closure`, or `provenance`. It parses and hashes each selected object in
one streaming pass. Multiple objects are scanned concurrently within the cgroup CPU budget.
The file size and modification identity must remain stable across the pass. Empty TriG, invalid RDF,
blank-node graph names, size/count overflow, mutable input, and immutable-store conflicts fail closed.
Successful discovery publishes a checksum-bound source manifest with per-object blank-node scope,
quad counts, graph counts, byte counts, SHA-256, aggregate SHA-256, and the stable logical partition
count. Status is read through `GET /v1/datasets/{datasetName}/imports/{operationId}`.

Kueue owns batch admission and the cluster autoscaler/Karpenter contract may scale the
`source-ingestion` node pool from zero. The worker uses bounded Rust tasks; OpenMP, BLAS, MKL, BLIS,
and Rayon remain at one lane to prevent nested oversubscription. The current source-freezing Job is
one multi-core pod. Multiple imports scale across nodes. One monolithic TriG object remains one
syntax stream: distributing its decoded quads across nodes requires the next syntax-aware
decode/shuffle/compiler handoff and must never be implemented as unsafe byte-range splitting.

This phase does **not** make the frozen sources queryable. It does not yet convert the cloud-source
manifest into the compiler's source plan, execute the distributed projection/index/reasoning stages,
or publish a snapshot. Provider-version/generation evidence is also not implemented, so the API
rejects `require-versioned-objects` and accepts only an externally enforced immutable-object policy
plus strong content hashes. Native Cargo/Helm and live CSI/Kueue/autoscaler qualification remain
release gates.

No ontology alignment or raw-data mapping functionality is present.
