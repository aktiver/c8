# Phase 40.13.11 — Cloud-source compiler handoff

This increment consumes only the immutable source manifest produced by Phase 40.13.10. It does not
perform ontology alignment, raw-data mapping, closure generation, OWL qualification, publication,
or query activation. Phase 40.13.12 is the first consumer of the verified compiler handoff.

## Graph namespace

The graph namespace is now:

- `https://c8-next-generation.io/<scope>/<subdomain>/semkg`
- `https://c8-next-generation.io/<scope>/<subdomain>/closure`
- `https://c8-next-generation.io/<scope>/<subdomain>/provenance`

The last segment remains mandatory. Only authorized asserted `semkg` graphs may later enter exact
ontology assembly; closure and provenance graphs remain acceleration/evidence artifacts.

## Distributed decode DAG

1. The discovery worker validates and hashes complete TriG objects and publishes the source manifest.
2. The largest-first planner groups complete objects into stable work items. It never splits a TriG
   byte stream because arbitrary byte offsets are not grammar-safe and may corrupt blank-node scope.
3. An Indexed Job maps each completion index to exactly one immutable work ID. Many objects decode
   concurrently across pods/nodes; a single very large object is streamed by one syntax parser.
4. Each decoder streams N-Quads to bounded scratch, verifies source size/hash/quad count before
   immutable upload, and publishes one completion manifest.
5. The finalizer requires every expected completion, verifies every fragment remotely by SHA-256,
   rejects gaps/duplicates/mismatches, and publishes one checksum-bound compiler handoff.

The plan and output identity are independent of current pod count. Kueue controls admission, pending
Indexed completions create node demand, and the external Kubernetes node autoscaler grows the
`source-ingestion` pool. Per-pod CPU lanes are cgroup-shaped; OpenMP/BLAS/MKL remain at one because
RDF parsing is not a dense numeric kernel. Memory and ephemeral storage are fixed requests/limits,
and object-store transfers use bounded multipart buffers.

## Fail-closed boundary

No compiler handoff is published after a missing completion, bad source hash, changed file metadata,
TriG parse failure, unexpected quad count, oversized plan/fragment, missing artifact, remote checksum
mismatch, duplicate/missing ordinal, or Kubernetes Job failure. Phase 40.13.11 does not claim that a
500 GB single TriG grammar stream itself can be parsed by multiple nodes; downstream decoded objects
and Phase 40.13.12 logical partitions provide inter-node fan-out without changing RDF semantics.
