# Phase 40.13.12 — Distributed Semantic Compilation

Phase 40.13.12 consumes only the checksum-bound `compiler-handoff.json` emitted after the
Phase 40.13.11 cloud decode barrier. It turns existing RDF/TriG source objects into inactive,
query-oriented storage artifacts without performing ontology alignment, authorization, OWL
assembly, reasoning, publication, or raw-data mapping.

## Execution graph

1. `cloud-semantic-map` is an Indexed Job with one immutable completion per decoded object.
   Each pod verifies its N-Quads fragment, scopes blank nodes by source-object identity, parses
   batches concurrently across cgroup-budgeted CPU lanes, hashes facts into topology-stable
   logical partitions, and externally spills sorted fact and term runs.
2. `cloud-semantic-dictionary` starts only after every mapper index succeeds. It verifies exact
   fragment coverage and externally merges term runs into a dense term dictionary plus a
   deterministic UUIDv5 entity dictionary.
3. `cloud-semantic-partition` is an Indexed Job with one completion per logical partition. Each
   reducer downloads only its fact runs, performs RDF set deduplication, and emits canonical
   N-Quads, Parquet facts, sorted forward/reverse adjacency indexes, predicate/class semantic
   indexes, and physical graph inventory.
4. `cloud-semantic-finalize` starts only after every partition succeeds. It concurrently hashes
   every remote artifact, validates exact partition coverage and checksums, and writes a single
   inactive semantic compilation root.

Kueue admits mapper and reducer pods to the `semantic-projection` worker class. Pending Indexed
Job workloads allow Kubernetes Cluster Autoscaler to add nodes; `mapMaxParallelism` and
`partitionMaxParallelism` cap simultaneous pods. Logical partition IDs depend only on dataset,
snapshot, source hash, and partition ordinal, so retries, pod replacement, node changes, and
parallelism changes cannot alter the compiled answer.

## Graph semantics and scope boundary

The compiler classifies but does not authorize graphs:

- `https://c8-next-generation.io/<scope>/<subdomain>/semkg` is an asserted-ontology candidate.
- `.../closure` is an inactive closure artifact and never asserted input.
- `.../provenance` is provenance and never asserted input.
- the physical default graph remains distinct and is not silently included in the service union.
- other named graphs remain named RDF and require an explicit later policy decision.

The root lists union-default and asserted-ontology *candidates*, with
`authorizationState=unqualified`,
`qualificationState=pending-owl2-dl-snapshot-qualification`, and
`publicationState=inactive`. Phase 40.13.13 must select authorized asserted `*/semkg` graphs,
resolve pinned imports, validate the combined OWL 2 DL snapshot, and bind qualification evidence
before Phase 40.13.15 can activate the snapshot.

## Failure and resource behavior

- Missing, duplicate, malformed, oversized, or checksum-mismatched inputs fail the stage.
- A missing mapper or partition completion prevents every downstream barrier.
- Mapper memory is bounded by spill rows; reducer fan-in, quads, row groups, artifact size, and
  verification concurrency have explicit operator ceilings.
- Workers use immutable object keys. Existing different bytes are conflicts, never overwrites.
- Finalization returns no partial root and never changes the active snapshot.
- OpenMP, BLAS, and Rayon stay at one lane in these symbolic stages; the mapper explicitly owns
  its CPU parser lanes while Tokio retains a small I/O control budget.

## Qualification boundary

The repository contains unit coverage for object-scoped blank nodes and the complete local
map/dictionary/partition/finalize pipeline, JSON-schema contracts, CRD status fields, Helm
resource ceilings, and a cumulative static gate. Native Rust, Helm rendering, cloud object-store,
Kueue, node-autoscaler, interruption, and multinode equivalence tests remain environment-bound
release gates and are not represented as passes by this candidate.
