# Phase 40.13.8 — distributed SPARQL algebra foundation

Phase 40.13.8 compiles every parsed query form into a checksum-bound post-order algebra DAG. Each
stage has an explicit execution lane, partition count, row/exchange/spill ceilings, dependencies,
and a complete-partition barrier. Ready leaf branches form deterministic concurrency waves that can
be scheduled across fragment-worker pods without making answer identity depend on replica count.

Native Rust kernels are deliberately limited to exact binding-level semantics: inner join, bag
union, expression-free left join, MINUS with SPARQL disjoint-domain behavior, projection, DISTINCT,
REDUCED-preserving execution, global slicing, group ownership, and k-way ordered-range merge. The
pinned scalar evaluator continues to own expression-bearing OPTIONAL, FILTER/BIND, aggregation,
RDF-term ordering, subqueries, paths, and ASK/CONSTRUCT/DESCRIBE finalization. Complete groups and
sort ranges are moved to workers; the native engine does not invent SQL NULL, collation, or
aggregate-error rules.

The normal exact-entailment query path now compiles and checksum-binds this complete DAG beside the
HermiT proof/certificate evidence. The Kubernetes fragment HPA observes fragment and algebra/shuffle
backlogs plus active spill pressure, CPU, and memory. Partition ownership is stable, and a later pod
or node count change cannot alter a stage checksum.

This source increment does not enable a complete-distributed-SPARQL claim. Native compilation,
worker RPC activation for every scalar-oracle stage, scalar differential equality, failure
injection, and live multinode autoscaling remain blocking qualification gates.

Ontology alignment and raw-data mapping are absent from this database workstream.
