# Phase 40.13.4 — Scalar SPARQL conformance repair

## Purpose

Make the scalar SPARQL path a more trustworthy correctness oracle before expanding distributed algebra, exact online reasoning, or Kubernetes scale claims.

## Delivered contract

- Semantic SELECT comparison treats the head as a variable set, rows as an ordered sequence or multiset as required, numeric/Boolean values by their RDF value, language tags case-insensitively, and blank nodes through graph isomorphism.
- Comparison is bounded by certified row and blank-node ceilings.
- Parser compatibility inserts only required comma token separation outside comments, IRIs, and strings.
- Retrieval base IRIs are applied to relocated syntax tests.
- CSV results accept blank-node relabeling but reject lexical-value changes.
- The official failing baseline is machine-readable and reconciles exactly to 12 cases.

## Evidence threshold

The Phase 40.13.4 gate fails if the pinned query/results inventory changes, passing cases drop below 326, failures exceed 12, or a failure appears outside the reviewed gap ledger. Passing fewer tests can never be hidden by editing the feature matrix.

## Non-claims

This phase does not establish complete SPARQL, complete distributed execution, online HermiT completeness, live Kubernetes autoscaling, or production readiness. Ontology alignment remains absent and out of scope.
