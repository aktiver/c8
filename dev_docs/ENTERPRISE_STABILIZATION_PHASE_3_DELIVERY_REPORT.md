# Enterprise Stabilization Phase 3 delivery report

Phase 3 adds a controlled, fail-closed release and live-infrastructure qualification path on top of the Phase 2 native build closure. It does not embed credentials, invent image digests, or substitute synthetic evidence for a real registry, PostgreSQL HA service, or Kubernetes provider.

## Implemented

1. Added an authoritative inventory for all twelve deployed OCI artifacts: eleven NGKG-built images and one approved vLLM image mirrored by immutable digest.
2. Made every Rust and HermiT image build consume locked, offline dependencies with Docker build-step networking disabled and all base images pinned by digest.
3. Added a multi-architecture Buildx release driver for `linux/amd64` and `linux/arm64`, immutable registry resolution, SPDX and CycloneDX SBOM generation, Grype and Trivy zero-high/zero-critical gates, SLSA-style provenance, Cosign image signing, signed SBOM/provenance attestations, and immediate signature verification.
4. Added checksum enforcement for the controlled runner's Docker, Crane, Syft, Grype, Trivy, Cosign, Helm, kubectl, PostgreSQL and Python executables. Toolchain evidence is bound into release evidence.
5. Added real PostgreSQL migration qualification for the core and agent catalogs using distinct migration-owner and runtime identities, TLS-required connections, exact digest-locked migrator containers, schema-before/schema-after hashes, SQLx ledger checks, a primary with at least one streaming replica, forced RLS, cross-tenant denial, and immutable-record negative tests.
6. Added atomic, digest-bound Helm deployment for the CRD, platform, workload and agent charts. Provider values remain external and contain only references to approved identities, Secrets, KMS keys, storage, network and autoscaler resources.
7. Added a real HA qualification harness for RKE2, EKS, AKS and GKE. Every cluster must have at least three ready schedulable nodes, three labeled failure domains and an actual GPU node.
8. Added API, OpenAPI/Swagger, cross-domain OWL 2 DL SPARQL, MCP session and tool execution, exact HermiT fallback, 80% CPU-and-memory HPA, node-autoscaler, physical node-loss, checksum rejection, backup/restore, vLLM scale-from-zero, inference draining and cross-tenant dataset/MCP/memory/tool/query-log scenarios.
9. Added approved external driver contracts for provider VM termination, cloud storage corruption/backup/restore, and real inference requests. A Kubernetes Pod deletion cannot satisfy the physical node-loss gate.
10. Added signed provider and database evidence plus a final issuer that re-verifies every OCI signature and attestation, every artifact checksum, every evidence signature, the exact image inventory, all four providers and all twelve scenarios before issuing a Merkle-rooted Phase 3 certificate.
11. Added a protected, manually approved GitHub Actions workflow with pinned action revisions and provider-specific controlled runners. It is not triggered by ordinary pushes or pull requests.
12. Added strict schemas, example configuration, fixtures, source acceptance checks and tamper-negative tests. Generated bytecode and compilation outputs are excluded from deterministic source manifests.

## Source validation completed here

- The supplied archive and all 1,390 bundled payload hashes were verified before modification.
- Phase 3 shell syntax, Python compilation, JSON structure, workflow YAML parsing, strict inventories and static security controls pass.
- The certificate verifier's complete synthetic fixture passes, then fails after a checksum-bound SBOM is modified. This fixture is explicitly test-only and cannot become release evidence.
- Phase 2's recorded native closure remains the applicable Rust/Helm evidence because Phase 3 changes release Dockerfiles, scripts, policies, workflow and documentation—not Rust application or Helm-template logic. That inherited result is 297 Rust tests, 18 release binaries and four linted/rendered charts.

## Infrastructure qualification status

No Phase 3 release certificate is included. This runner does not provide Cargo/Rust, Docker/BuildKit, Cosign, Syft, Grype, Trivy, Crane, Helm, kubectl, psql, an OCI registry, a PostgreSQL HA service, or dedicated RKE2/EKS/AKS/GKE clusters. Therefore OCI construction, vulnerability scanning, signing, migration application, node termination, autoscaling, HermiT runtime execution, GPU inference and live tenant-isolation tests were not falsely reported as complete.

The protected workflow in `.github/workflows/phase3-controlled-release.yml` is the exact execution boundary. It will fail without reviewed tool hashes, preseeded offline dependencies, immutable base images, provider values, mode-0600 tenant tokens, disruption approval and real infrastructure.
